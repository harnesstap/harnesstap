## harnesstap v1.5.0 - October 18, 2026

### Added


  - A profile can now keep in sync with a parent profile. A profile whose upstream link has `kind: "extends"` shows the parent's items live, at the newest installed parent version inside its range (never a new major), minus the items it hides, plus its own; its own item wins on a name clash. Apply, preview, `ht profile show` and the dependency resolver all use this composed set, so a parent edit reaches every child with no copy step. A missing parent stops apply with the `ht profile pull` command to run, and a profile cannot extend itself directly or through its parents. Hidden items are stored per profile and frozen with each `ht plugin cut`; each names one item exactly (no patterns), up to 200 per profile, matching what Cloud accepts. This adds a table to the local database (schema v41), so older builds cannot open it. The commands to duplicate, hide and detach come in follow-up changes.

  - Exported and published packages now carry a keep-in-sync link. A profile that extends a parent writes `extensions["com.harnesstap"].upstream` with `kind: "extends"`, plus `exclude`, the list of parent items it hides (`<type>:<name>` or `plugin:<name>`). `exclude` is written on the root manifest only, never in embedded packages. A child of a local parent gets its parent's catalog ref once that parent lives in a catalog. Installing such a package keeps the link and the hidden list; `exclude` is ignored on a fork or in an embedded package, entries with an unknown type are dropped, and a package that would extend itself is refused before anything is written.

  - `ht profile duplicate <source> [name]` duplicates a profile. The default keeps the copy in sync with the source: it starts empty and shows the source's items live. `--copy` makes a separate copy (a fork). `ht plugin edit <name> --hide skill:review` hides an inherited item on a kept-in-sync profile and `--unhide` shows it again; `ht plugin show` lists the hidden items and how many items come from the parent. `ht profile detach <name>` turns a kept-in-sync profile into a separate copy in the Library: its current items become its own, the link still shows "Forked from", and nothing is applied or deleted. Publishing a kept-in-sync profile whose parent is not published is refused before any version is cut or any network call, with `ht profile detach` as the way out; Cloud's `upstream_unpublished` answer shows the same message. `ht plugin publish` plan JSON and the Desktop publish plan list it under `blockers`, and publishing returns 409. `--to <org>/<catalog>` duplicates a catalog profile in Cloud and publishes it there, falling back to the Library when Cloud cannot duplicate yet. Publish errors from Cloud now name the hidden item it rejected or the parent ref that is not published, with the request id. With `--to`, a name Cloud cannot turn into a slug is refused before any request, and Cloud errors say what to fix: a taken slug (with another name to try), a hidden or missing source, an unknown organization or catalog.

  - Desktop: one **Duplicate** button replaces Fork on every Library plugin, authored ones included. The dialog asks for a name and offers **Include as a resource of a new profile** (the default; the new profile contains the source and gets its updates) or **Separate copy**. In Edit profile, a kept-in-sync profile lists its parent's items with a "from parent" chip: untick hides one, tick shows it again, and both can be undone from the toast. **Detach from parent** copies the parent's items into the profile and stops parent updates; nothing is deleted. The publish drawer shows why a kept-in-sync profile cannot publish while its parent is unpublished and keeps Publish off. The agent adds `POST /v1/library/plugins/:selector/duplicate` (`{name, mode: "inherit" | "copy"}`), `POST .../detach` and `PUT .../excludes` (`{entries}`); `/fork` still works. Profile and plugin detail now return `upstream`, `excludes` and the `inherited` items, each tagged `source: "parent"` with a `hidden` flag.

  - `ht plugin check` now also checks every upstream link (kept-in-sync and separate-copy profiles, and pulled catalog packages) for newer versions and stores the answer in a local table (schema v42, `upstream_checks`), so `ht status` and Desktop can read it without a network call. The newest version inside the link's range is offered as an update; a newer major shows as `major` and is never installed automatically. Cloud being unreachable or a parent not being published is recorded, not a failure. "Not now" remembers the version it set aside, and a newer version shows up again. JSON output adds an `upstream` array. Checks use Cloud's batched updates-since endpoint (100 refs per request, ETag so an unchanged answer is not downloaded again) and fall back to one lookup per plugin on an older Cloud; a yanked version is not offered.

  - `ht status` shows one Updates row when the last upstream check found something, for example `2 updates available (ht plugin update --all)`, and says separately how many major versions are available and not installed automatically. The status payload (`ht status --format json`, `ht profile status --format json` and the agent status route) adds `updates: {count, major_count, items}`. It reads the stored check result only, never the network; versions set aside with "Not now" are left out. Writing check results does not force a status recompute, and the status time budgets hold with 200 stored results.

  - The Desktop sidecar checks upstreams for newer versions shortly after it starts and then every 6 hours, one check at a time; `HARNESSTAP_UPDATE_CHECK=off` turns the schedule off. A banner at the top of the Global view says how many updates are available, with **Update all** and **Not now**; Not now sets aside the versions on offer, and a newer version shows the banner again. A separate copy is named with the upstream version and gets no Update all, and a newer major is counted but never installed automatically. Profiles that are, or use, a plugin with an update get a small dot in the rail. The agent adds `GET /v1/updates`, `POST /v1/updates/check` (202 with a job id), `GET /v1/updates/check/:job_id` and `POST /v1/updates/:plugin/dismiss`.

  - New `updates` settings in `config.jsonc`: `mode` (`off`, `notify` (the default) or `install`), `frequency` (`hourly`, `daily` (the default) or `weekly`) and `prompted`. The Desktop sidecar checks when a check is due under `frequency`, counted from the newest stored check. In `install` mode it also installs, for pulled catalog plugins, the newest minor or patch inside the caret range. It never installs a major version, skips plugins whose content no longer matches the published version (local edits) and separate copies, keeps the previous version as a frozen cut, and re-applies the active profile only when its harness files are clean. One plugin update runs at a time; `ht plugin update` waits for a scheduled run, and Desktop Update all returns 409 `update_in_progress` after waiting 60 seconds.

  - `ht plugin auto-update` shows or changes how plugin updates are checked (`--mode off|notify|install`, `--frequency hourly|daily|weekly`). After the first successful `ht plugin update --all` in an interactive terminal, HarnessTap asks once "Keep these up to date?"; non-interactive runs never ask. Desktop asks the same once after the first Update all with no failure (Save or Not now), and Settings > Advanced gains a Plugin updates section that saves inline. The agent adds `GET` and `PUT /v1/settings/updates`.

  - Local notifications: a new `notifications` table (schema v43) records when a check finds a new plugin version, when a kept-in-sync parent publishes, when install mode updates a plugin, and when update checks keep failing. The same version is never notified twice. `ht notifications` lists unread ones (`--all`, `--format json`), `ht notifications read <id>` or `read --all` marks them read, and `ht notifications prune --older-than 90d` deletes old read ones only after confirmation (or `--yes`). Nothing is deleted otherwise.

  - Desktop shows a notifications bell next to Settings with the unread count. Its popover has Unread and All tabs, Mark as read on each unread notification, and Mark all as read. The agent adds `GET /v1/notifications?filter=unread|all&limit=`, `POST /v1/notifications/:id/read` and `POST /v1/notifications/read-all`, and the status payloads include `unread_count` so the bell needs no extra call.

### Changed


  - `ht profile pull` and catalog installs keep the catalog identity. The local plugin is named after the catalog slug (`backend-engineer`, not `Backend engineer`) and stores the real package version instead of the word `latest`. It is no longer marked as edited, and `ht profile pull` tags it as a profile. `ht plugin check` and Library no longer report an update right after a pull, and pulling `@1.0.0` after a plain pull reuses the same plugin. Plugins pulled before this change keep their names.

  - `ht plugin publish`, `ht profile publish` and Desktop Publish now refuse a plugin that depends on a local plugin that is not in a catalog, because nobody who installs it could fetch that dependency. Before, they only printed a warning. The error names the dependencies and the `ht plugin edit --remove` command that removes them. `--version` no longer cuts a version when the publish is blocked. Marketplace, git, catalog and embedded dependencies are not affected.

  - Desktop profile screens are leaner and use one noun, "profile". The Library detail and the profile page share one header: Edit, Duplicate, Tags and History as icons, then a 3-dot menu with Refresh from origin, Run Doctor, Publish, Detach and, last and in red, Delete; every icon has a tooltip and there is no always-visible trash. A profile's Library detail no longer has its own Apply (the sidebar Apply is the one place to apply), and its type shows as a chip under the title. Duplicate is also on the profile page; the dialog is titled "Duplicate profile", checks the name as you type, and its toast opens the new profile. A kept-in-sync profile lists its parent's items inline in Composition with a link icon; hidden ones stay in place, dimmed and struck through, with an eye-off icon, and a chip under the title says what it is synced with. The edit pane saves as you go (no Save or Discard); edits stay in the Library until you Apply. Detach happens at once and its toast offers Undo for 10 seconds, which puts back the link, the hidden list and the item order. "Edited" replaces the `*` after a version, and tooltips no longer linger after a dialog closes.

  - Desktop: the updates banner now shows only on the page of the profile it affects, as a neutral notice ("acme-lint: 1.2.0 is available (you have 1.0.0).") with Update and a Dismiss button, and it clears after the update. Majors and separate copies no longer appear in the banner; they go to the bell. The profile rail marks profiles with an update with an up-arrow badge (tooltip "Update available") in a fixed slot, and long names truncate instead of wrapping.

  - Plugin update settings use plainer words. The one-time prompt is now "Keep plugins up to date?" and appears only after an update that installed something. Off reads "Never check. Synced profiles still follow their parent.", Notify only reads "Tell me. I'll install.", and Install automatically reads "Minor and patch updates install on their own. Majors always ask." The frequency field is labelled "Check for updates" and is disabled when Off. The defaults stay Notify only, checked daily, in both the prompt and Settings.

  - Notifications use shorter words. A synced profile reads "backend-qa now uses 1.1.0" with "Synced from backend (was 1.0.0).", an automatic install reads "acme-lint updated to 1.2.0" with "Installed automatically. 1.0.0 kept so you can roll back.", and a major reads "Major update, needs your OK."

  - Desktop notifications: unread rows have a leading dot, and clicking a row marks it read and opens the profile it is about (a plain plugin opens in the Library). Mark as read is a check icon on row hover or focus, Mark all as read is a double check in the header, and the empty Unread list says "All caught up." The unread badge uses the accent color instead of red. Reading an update notification also clears the rail badge for that version; a newer version shows it again.

  - Desktop: resource badges on the profile page are pills, shaped like the resource type tabs, with their actions hidden until you hover or focus them. The pill then grows to the right to show them (+, x, Use on, and the Also use on suggestion as icon buttons with tooltips) without moving any other badge: the actions overlay their neighbours, and every row keeps room at its end so the last badge never overflows. A small dot marks a badge with an Also use on suggestion.

  - Desktop Edit profile: the Default environment field shows only an "Add default environment" button until a default is set. Add picks the first environment and shows the dropdown, which no longer offers "None". An x with the tooltip "Remove default environment" clears it back to the Add button. Both states keep the same height, and the choice autosaves like the rest of the pane; harness files change only on Apply.

  - Desktop: resource pills on the profile page show the name only. A small circle after the name marks a resource that is not on every tool: the tool's logo when it is in one, or how many when it is in several. The tooltip says where it is ("Only in Cursor and Codex"), and screen readers get the same text. Each type section shows one suggestion line instead of a prompt on every pill, for example "3 MCPs could also run on Cursor and Codex", with Add all and Dismiss. In edit mode, the Tools button on a pill opens one checkbox per tool and saves into the draft as you go; the last tool cannot be unchecked. OpenCode resources show the OpenCode logo instead of a yellow question mark.

### Fixed


  - The npm CLI no longer prints two `[status-cache] refresh worker error` stack traces on `ht profile use` and `ht profile status`. The status refresh worker now ships in the package as `dist/status-refresh-worker.js`, so status reads run on it instead of failing to load it and falling back.

  - `ht profile status` and the Desktop footer no longer say "out of sync" or "Not fully applied" right after an apply when Cursor reads a skill from `~/.agents/skills`. Status expected a copy in `~/.cursor/skills` that apply never writes, because Cursor already reads the shared folder. Status, preview and apply now agree. A harness added with `ht resource scope` is still reported until apply writes its copy.

  - A Claude plugin added from git or a local folder (for example `ht plugin add DietrichGebert/ponytail`) is reported as installed after apply. Status and the Desktop "Install gaps" list called it "not installed" and listed `ponytail@local` as extra, because HarnessTap registers these plugins as `<name>@local` while the profile pins `<name>`.

  - Discover can add plugins from the built-in cursor-public marketplace to the Library or a profile without running `ht marketplace add` first. Before, Add to Library failed with "Marketplace not found: cursor-public".

  - Unticking a dependency in Desktop Edit profile removes it. Before, when the dependency plugin was not in the Library (for example a pulled catalog profile), unticking added a second `feature-dev *` entry. Undo in the toast now restores the dependency with its original constraint, and the sidecar never attaches a second copy of a dependency.

  - `ht profile status`, `ht profile preview` and the Desktop preview no longer list the images of a Claude host plugin (for example the 45 PNG and JPG files of ponytail) as "out of sync" or "Will write" right after an apply. Binary files are compared byte for byte with what apply would write, so status and preview agree with apply.

  - `ht profile create <name>` on a plugin that already exists at a version other than 1.0.0 now tags that plugin as a profile, as it already did at 1.0.0. Before, it created a second, empty plugin with the same name that `ht profile list` and Desktop did not show. `--version` on an existing plugin at another version is refused, and nothing is created.

  - CLI counts use the singular for one item: "Kept 1 file", "To remove it too", "Stashed 1 change. Bring it back", "Would stash 1 change", and list summaries such as "1 resource", "1 plugin", "1 snapshot", "Update 1 plugin from origin?" and "1 change" in plugin diffs.

  - A fork now remembers what it was copied from. `ht plugin fork` and Desktop Fork store an upstream link: `{kind: "fork", ref, version_at_link}`. For a catalog source the ref is `org/catalog/slug@^x.y.z`. `ht plugin show` and the Library detail show "Forked from", and `--format json` and the API return `upstream`. Exporting or publishing a fork of a catalog plugin writes the link to `extensions["com.harnesstap"].upstream`, and installing such a package keeps it. The link survives `ht plugin cut`. This adds columns to the local database (schema v40), so older builds cannot open it.

  - Desktop: profile names in the Profiles sidebar use the full row width. The drag grip and the Edit button used to keep about 90px of each row empty even when hidden, so names wrapped early. They now appear over the row on hover or focus, so nothing moves. A name too long for the row ends with an ellipsis and shows in full in a tooltip. The in-use mark takes a smaller slot before the name.

## harnesstap v1.4.0 - October 16, 2026

### Added


  - ht plugin validate loads an Agent Plugins 1.0.0 package and reports skills, MCP servers, skipped entries, and ignored manifest fields. Import follows those rules. A bad mcp.json disables MCP and keeps the skills. Invalid skill names are renamed on export, and secret-like MCP env or header values move to com.harnesstap.

  - A root plugin.json with the Agent Plugins 1.0.0 schema imports as an agent plugin. Author, homepage, repository, license, and vendor namespace trees are kept and written back on export. Manifest path overrides are ignored.

  - Marketplace catalogs also read Copilot `.github/plugin/marketplace.json` and Codex `.agents/plugins/marketplace.json`. A listed root with the Agent Plugins 1.0.0 schema is classified as an agent plugin.

  - Codex and Copilot can load Agent Plugins packages natively when harnessSync.nativeAgentPlugins is true. The portable extract for those packages stays off, and uninstall removes only the HarnessTap plugin keys.

  - plugin publish checks the Agent Plugins package before upload. A wrong manifest schema or an unusable mcp.json always blocks. Other export warnings block only with --strict. --vendor-extensions writes Copilot files and Codex hook settings, and migrate export can write a zip.

### Changed


  - MCP servers keep spec cwd and an HTTP transport of streamable-http or sse. Apply warns when a harness cannot write those fields. Plugin variable translation and the plugin data directory are available for emission.

  - Cursor and Claude copies of an Agent Plugins package rewrite plugin variables in the emitted tree only. Unmanaged files in a Cursor local plugin are kept, and owned removals are backed up.

  - HARNESSTAP_STATUS_CACHE_DEBUG=1 now prints per phase status timing lines to stderr.

  - Status recomputes reuse unchanged work. Unicode scan results, skill companion files, drift comparisons and per resource ownership paths are kept between reads in the same process, and the dry run plan reads each file and each materialization root once.

  - Desktop no longer shows a Main badge in the Use on picker, and the harnesses there are listed A to Z. Every registered harness is treated the same, so the badge and its tooltip were misleading.

  - Docs and `ht help` describe harnesses as one registered set. The first registered harness is the default for `mirror` and single-harness scans; there is no separate main harness. Scenario 2 now uses `ht harness set --harnesses`. The hidden `--main` and `--aliases` flags, `--reference main`, and `main_harness` in requests and archives are still accepted.

### Fixed


  - A profile or plugin apply no longer cancels when the only difference is formatting HarnessTap would leave unchanged. A real cancel names the file and hints at --on-conflict.

  - Desktop confirm dialogs take focus, keep Tab inside the dialog, close on Escape, and return focus to the control that opened them.

  - Profile preview and status include a harness file that a scope change would write, including when another harness already has a copy it cannot read.

  - Desktop Discover no longer shows the CLI catalog timeout. A crashed agent splash uses a short headline, and paths shorten with the real home directory.

  - Profile preview uses the same kept-or-remove groups as the apply confirm dialog, including the group totals. A preview refresh after apply does not reuse a fetch from before the write.

  - Applying a git-imported Claude plugin registers it in installed_plugins.json and enabledPlugins. Its skills stay inside the host plugin tree instead of being copied out as standalone skills.

  - CLI hints use ht and quote names that contain spaces. One change is singular. Empty plugin descriptions and tags no longer render as a bare colon. Tables clip with ASCII dots and keep colored profile names. A denied device login omits the HTTP status. A no-op profile re-apply does not save another snapshot. Kept files are not also warned as skipped removals. Scenario playbooks print links as text.

  - A hand-edited managed file is labeled kept on switch-back preview, is not cancelled as a write, and does not leave the active profile out of sync.

  - Apply and profile-switch result lines count kept files together with writes and removals, including when nothing was written or removed.

  - Remove profile focuses Cancel. resource show shortens home paths with ~. profile use --dry-run lists planned writes instead of cancelling on conflict. The replace hint says "them" when more than one file would change.

  - Host MCP configs expand PLUGIN_ROOT and PLUGIN_DATA to the installed package path, resolve a relative command as one token, and keep cwd on harnesses that store it. ([#429](https://github.com/harnesstap/harnesstap/issues/429))

  - With native Agent Plugins on, an untouched Codex or Copilot config is not reported as a change when no @harnesstap keys need to be added or removed. ([#430](https://github.com/harnesstap/harnesstap/issues/430))

  - Marketplace catalogs read every manifest, label each plugin with its flavor, drop source paths that leave the repo, and sync a local pin without a resource conflict. A missing marketplace plugin names `ht resource sync`. ([#427](https://github.com/harnesstap/harnesstap/issues/427))

  - Desktop preview counts hand-edited and unmanaged files as kept. Human migrate export prints a home path as ~/. Vendor hook scripts outside the package are bundled with a relative path, or omitted with a warning.

  - Attaching a marketplace plugin whose source path leaves the repository is rejected, and no pin is recorded. ([#440](https://github.com/harnesstap/harnesstap/issues/440))

  - Host MCP configs expand plugin paths for marketplace, git, and local installs, using the same resolution as an imported package. ([#438](https://github.com/harnesstap/harnesstap/issues/438))

  - Host MCP configs follow the current platform, cancelled profile switches omit the native agent plugin cache, the Desktop apply footer ignores kept rows, and pin hints use `ht`.

  - Resource detail and resource show read the on-disk file for a live library ref such as a shared AGENTS.md, instead of the empty stored content.

  - Resource detail stays responsive while a marketplace git refresh is in progress. A stale catalog is served immediately and refreshed in the background. Reveal returns without waiting for the file manager.

  - Active plugin chips that share a name show the marketplace or harness, and both copies stay in the list.

  - Status reuses a full read until the profiles database, harness config, Cursor plugin directories, or marketplace manifests change. It does not read Cursor's state.vscdb or logs folder. A plugin under ~/.cursor/plugins/cache counts as installed even when Cursor has it turned off, using the newest version directory, along with marketplaces/, local/ (including HarnessTap-managed copies), and plugin-* MCP folders. File watchers mark that cache dirty once per path, and a warm read is a lookup. When inputs change, the previous status is served with refreshing set while a new read runs on a background thread, so a warm read does not wait on that work. Plugin name lookups prepare their SQL once. Apply, switch, and install drop the cache immediately. Whether Cursor loads other harness trees is read from settings.json only, and defaults to on.

  - Desktop polls live status every 8 seconds, and only while the window is visible and focused. A poll does not start while an earlier one is still running.

  - Marketplace manifest reads are reused when the file has not changed, including plugin-name checks. Hidden-Unicode scans are reused for the same content, and a scan is skipped when the file mtime and size are unchanged.

  - Desktop update checks are reused for one hour.

  - Status computes a cold read on the background worker started with the desktop sidecar, keeps that worker and its file watchers alive, and returns a frozen snapshot. Hidden-Unicode checks skip files that will not be written and skip unchanged files by mtime and size. A Cursor plugin-* MCP folder uses the plugin ref from its manifest or cache directory, and is not listed twice when that plugin is already cached.

  - Status arms file watchers on the refresh worker, so a warm read after a cold start stays on the request thread. A write to the HarnessTap database, including its write-ahead log, is included in the next status.

  - Warm status reads are served from the cache again. Status no longer compares file stats of the HarnessTap database and its write-ahead log, which change on plain reads. A write that changes a profile, from the app or the CLI, is included in the next status. Adding a library resource that no profile uses does not refresh status.

  - Status computes faster on a home with many installed plugins. One status read reads Claude installed_plugins.json, each plugin manifest, and each marketplace manifest once instead of once per plugin, and no longer rewrites every upstream plugin row.

  - `ht profile status` exits after printing. It no longer waits forever on the background status worker.

  - The desktop sidecar compiled with Bun 1.3 answers status again. Its status refresh worker failed to load, so every status read returned 500. The worker now loads under Bun 1.3 and 1.4, and if it fails to start, crashes, errors or does not reply, the read is computed on the agent thread instead. The Windows sidecar computes status on the agent thread. A failed read reports the underlying error and its stack, and no longer keeps `ht` from exiting. Project drift skips older snapshots that have no platform files.

  - Desktop Library rows, their dividers, and their hover and selected backgrounds span the full width of the list again on every tab and in both scopes.

  - Adding a plugin to a profile from Discover no longer asks "Some files will not be removed" about shared configs such as `.claude.json`, `.claude/settings.json` or `.cursor/mcp.json`. Those files are merged key by key, so edits the harness or you made to other keys since the last apply are not kept files. Your keys are still preserved, and user-modified files that apply writes whole are still kept and reported.
