## harnesstap v1.6.1 - October 25, 2026

### Changed


  - Desktop source builds: Cargo.lock now matches the app version and the generated Tauri schema files are no longer tracked, so a fresh build leaves the working tree clean.

  - Desktop: the top bar now has five equal tabs, Library, Discover, Env, Harness and Profile, with exactly one active at a time. The Scope label and the Global | Project switch are gone from the header. Open Profile to see your profiles: its page header has a Global | Project: <name> switch, and the chevron next to the project name opens the project list. The selected side is filled and in bolder text, and the switch keeps the same size whichever side is selected, so the chevron is always visible; a long project name is shortened and its tooltip shows it in full. In the project list, the current project has a check mark, and the folder button (Open another project) picks one that is not listed. If no project is set yet, clicking Project opens that list instead of an empty page. The app remembers the last scope you picked across restarts (Global on first run), and Library and Environments keep using it. Harness stays global.

  - Desktop Discover: Add to profile now asks which profile to add the item to, adds it without applying, and offers Undo in the confirmation toast; Undo removes only what was just added and keeps the Library copy. Each row shows Add to profile as its main action, with Add to Library next to it; Pin to a plugin moved to the item detail view. When a marketplace cannot be reached, the banner names it, has a Details toggle with the raw error and a Manage marketplaces button, and the last known marketplace list stays visible. The sidebar search placeholder reads "Search by name, description, or skill", the source list uses the same section labels and spacing as Library, All sources is a tri-state parent of its sources, and descriptions start with a capital letter. Pressing Escape in an open dropdown inside a dialog now closes only the dropdown.

  - Desktop: filter placeholders now say what they match (name and description, or name, type, and source), and every filter miss reads No matches for "query" with a Clear filter action at the same spot under the filter.

  - Desktop: disabled buttons now look disabled and say why on hover; the Library delete dialog has one Delete button with an opt-in "Also delete files on disk"; the kept-files, detect, and sync dialogs use plainer copy and clearer buttons.

  - Desktop: "From project" options in Create profile, Create environment and Import now offer an inline Choose project button, Settings > Project shows a single "Open a project to see its config." empty state, and Settings > Advanced reads more clearly (Check every, left-aligned actions, a locked telemetry switch when HARNESSTAP_TELEMETRY is set).

  - Desktop: the profile header keeps only Edit and History as icons (Duplicate, Tag, Install, Project history, Overwrite and more move to one menu); the rail pencil, the Active Edit toggle, the Library funnel clear and header Import are gone; Composition add sits on its heading; profile tags are removable pills; Target preview counts read "1 subagent" and "N file changes".

  - Desktop Harness page: Refresh, Edit, Detect, Sync and Add harness now sit in the page header with tooltips, and the empty state offers Detect harnesses plus an Add harness link.

  - Desktop: header tabs read "Environments" and "Harnesses" like the palette, Ctrl+5 opens Profile, Export and Import ask a plain question per step with a "Choose file" picker, Account uses normal-width buttons with Cloud and GitHub sections, Add marketplace shows the inferred type read-only, the Library drops repeated labels, and the create picker shows every type at 1440 wide.

  - Desktop: zero-count type chips are hidden everywhere (All stays), the overflow is a "+N" button, and chips line up with the filter. One Active/Inactive status pill replaces the ad hoc badges, the reconnect banner is neutral with a spinner and plain copy, changed-type badges explain themselves, harness icons have tooltips, names underline only on hover, row checkboxes center on the first line, versions read "v1.0.0" next to the name, and harness instruction chips show "CLAUDE.md" with the harness icon.

  - Desktop no longer tells you to run commands: the apply snapshot dialog has a Revert button, the harness banner and load errors point at in-app actions, and pending approvals no longer show CLI hints.

  - Desktop restarts its agent by itself when it stops responding, and the offline splash and reconnect banner offer a Restart agent button instead of telling you to close processes or check folders.

  - Desktop no longer shows command instructions from the agent: recovery buttons say Install or Fetch instead of a CLI command, error text drops "run ..." hints, and a project folder without a git remote (or without git) now keeps snapshots, drift, History and revert in the CLI and Desktop, keyed by its folder path. When the folder later gains a remote, its history moves to the remote-keyed project automatically after a database backup in ~/.harnesstap/backups.

### Fixed


  - Desktop: a failed load now shows one "Couldn't load ..." state with Retry (Env, Harness, Profiles) and hides create actions; Env shows its empty state in the main pane, lists "Used by profiles" as pills that open the profile, and delete dialogs use red Delete buttons with matching wording.

  - Desktop Profile page: an attached plugin is listed once instead of twice; when no harness is set up, the warning has a Set up harness button that opens Harness and detects harnesses; the History button opens the profile version history, and picking a frozen version opens it in Library without the tracked folders intro; Tag version prefills the next patch version, labels the field Version, and only shows errors after you edit it (also in Library); the warning banner has a 12px gap below it, and Edit composition no longer leaves a gap above Default environment.
