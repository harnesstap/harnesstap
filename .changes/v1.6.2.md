## harnesstap v1.6.2 - November 03, 2026

### Added


  - Homebrew install: `brew install harnesstap/tap/harnesstap` for the CLI and `brew install --cask harnesstap/tap/harnesstap-desktop` for Desktop on macOS. Each release updates the tap, and the CLI update notice suggests `brew upgrade harnesstap` for Homebrew installs.

  - MCP servers can set `enabled_tools` and `disabled_tools`. Codex writes them as is, Gemini CLI as `includeTools` and `excludeTools`, Kiro and Droid as `disabledTools`, and Copilot uses `enabled_tools` as its `tools` list.

  - Gemini CLI MCP servers: HarnessTap merges them into `mcpServers` in `.gemini/settings.json` (or `~/.gemini/settings.json`) and keeps your other settings.

  - Kiro: MCP servers in `.kiro/settings/mcp.json`, hooks as one file each in `.kiro/hooks/`, and skills in `.kiro/skills/` (skills in `.agents/skills/` are still scanned).

  - Zed MCP servers: HarnessTap merges them into `context_servers` in `.zed/settings.json` (or `~/.config/zed/settings.json`) and keeps your other settings and comments.

  - Droid MCP servers in `.factory/mcp.json` (or `~/.factory/mcp.json`), merged with the servers you already have.

  - GitHub Copilot path-scoped rules: rules with globs become `.github/instructions/<name>.instructions.md` files with `applyTo` frontmatter, and those files scan back into rules.

### Fixed


  - `ht apply --dry-run` (and the Desktop apply preview) no longer fails with "No local version of ... is installed" when a dependency pinned to `*` or a range is not installed yet; the plan resolves it from the marketplace and shows "would install <plugin> <version>" without writing to your harness or plugin cache. A dry run also no longer registers marketplaces with Claude Code or Cursor, and no longer marks exact pins as synced, so the next real apply installs them fully.

  - Desktop: a plugin that the profile names more than once (repeated plugin, repeated pin, or a pin plus the installed plugin) now shows as one chip, and the plugin counts follow.

  - Desktop: when Apply fails because no harness is set up, the error offers a Set up harness button that opens harness detection, instead of a Retry that fails again.

  - Desktop: adding an item to a profile now confirms it with a toast that names the item and profile (one combined message when you create and add in one step), and a failed add shows one error with the reason and Retry instead of a second banner.

  - Roo Code rules are written as plain files under `.roo/rules/` instead of into `.roomodes`, which is the custom modes file. A `.roomodes` an earlier apply wrote is backed up and removed; when you also edited it, only the rule sections that still match what HarnessTap wrote are taken out, and every other section, including one you added text under, is kept with a warning.

  - Antigravity rules in `.agents/rules/` now carry the `trigger` frontmatter Antigravity requires (`always_on`, `glob` with `globs`, `model_decision` with `description`, or `manual`), so Antigravity no longer discards them.

  - Antigravity commands are written as skills (`.agents/skills/<name>/SKILL.md`) because Antigravity stopped reading workflows. Workflow files an earlier apply wrote are backed up and removed; edited or unmanaged workflow files are kept with a warning.
