## harnesstap v1.6.3 - November 16, 2026

### Fixed


  - Desktop meets 4.5:1 contrast with the shared palette. Primary actions use a darker blue fill with white text, destructive-dialog confirms use a darker red fill with white text, and other danger UI uses a tinted red pair. Blue text on dark uses a lighter link blue. Brand blue stays on the mark, focus rings, and non-text accents. CLI badges use the same action fill.

  - Desktop dark success text uses a lighter teal so status and success UI meet the shared contrast target. CLI success color is unchanged.

  - Remote MCP servers keep their settings across harnesses: Codex reads and writes request headers as `http_headers`, Cline gets `type: streamableHttp` instead of falling back to legacy SSE, other plain `mcpServers` files no longer get a stray `protocol: sse` key, and scans read the `serverUrl` (Antigravity, Windsurf) and `httpUrl` (Gemini CLI) forms as remote servers instead of empty local ones.

  - GitHub Copilot and Copilot CLI project MCP servers are written to the workspace .mcp.json that Copilot reads, instead of .copilot/mcp-config.json. Existing servers move over on the next apply.

  - Windsurf and Devin follow the Devin Local layout: rules go to .devin/rules/ with trigger frontmatter, MCP servers merge into .devin/mcp_config.json and ~/.config/devin/mcp_config.json, and Windsurf skills are written as skill folders. Devin global MCP no longer goes into ~/.config/devin/config.json.

  - `ht apply --update` that a conflict cancels no longer rewrites `apm.lock.yaml`. The lockfile is written only after the apply succeeds, so the next apply still removes files the earlier version deployed instead of leaving them behind.

  - Kilo Code skills are written to .kilo/skills/ and ~/.kilo/skills/, the folders current Kilo reads. Skills in the earlier .kilocode/skills/ folders are still scanned and stay in place.
